# Prompt Fairy｜發佈會用進化紀錄（Draft）

> 這份不是正式 changelog，而是把值得在發佈會上講的「小精靈怎麼一路長大」先收起來。之後再依實際發佈版本刪減、重排。

## 核心方向的變化

- 從「把整份 Prompt 拆得很細」轉成「使用者只勾想改的部分，小精靈只抽出相關內容」。
- 目前主分類收斂為：人物｜衣著／小道具｜動態描述｜背景｜鏡頭語言｜濾鏡。
- 未選取、未授權修改的原文保持不動；小精靈的價值不只是會改，而是知道哪裡不該碰。
- 參考圖開始和人物身份錨定分工：參考圖處理角色靜態身份，其他姿勢、服裝、背景、鏡頭等除非被點名，仍以原文為準。
- 多角色方向改成「先解析角色，再對應槽位」，不再以性別硬猜 AA／BB。

## UI / 使用體驗

- 初版各頁曾經高度、寬度與卡片比例各走各的，像每頁都準備放飛；後來直接以整頁框架圖把頁面寬度、內容區塊與對齊基準鎖住，才建立現在一致的 layout contract。
- 整體工作台重新整理閱讀層級、留白、按鈕與提示卡位置。
- 中文閱讀字體改為較清楚的圓體系，改善小字辨識。
- 「清除選擇」避免折行；提醒卡重新對齊、統一高度與色系。
- Advanced Semantic Index 維持進階功能定位，平常可收起；展開後切換分類不會再自己縮起來。
- 修正「三分之四身」→「四分之三身」等 QA 文案與分類字典問題。
- Mojito review 補齊淺色主題的次級／ghost 按鈕映射，避免 Arcane 的深色按鈕樣式外溢到淡色頁面。
- 淺底區塊的 muted text、分類／分段控制重新拉開對比，讓未選取、hover、active 狀態可辨識。
- 胖譜庫沒有代表圖時改用 compact placeholder，不再讓空圖片框維持大張 4:3 視覺重量。
- 桌機雙語導覽改成等寬 cell：以現有最寬的 Character Library 格為基準，其餘導覽格向它看齊，兩行文字各自在格內置中。

## 人物槽：從 AA / BB 寫死到可增減

- 人設台初始只保留一個人物槽，不再一進畫面就固定 AA、BB 兩張卡。
- 可用「＋ 加入其他角色」往下新增 BB、CC、DD…。
- 每個人物槽有自己的穩定 internal id；AA／BB／CC 是對外顯示與 Prompt 使用的 slot token，不等同人物身份或性別。
- 中間槽位被刪除時不再讓後方角色自動遞補：例如 BB 被清空時，CC 仍然是 CC，避免已排好的參考圖／角色 mapping 被悄悄改位。
- 最末端空槽仍可真正移除，避免累積無意義空卡。

## 本機圖片整理

- 胖譜與人設可各存一張本機代表圖，方便整理時快速辨識。
- 圖片獨立放在瀏覽器 IndexedDB，不直接塞進文字用 localStorage。
- 明確提醒：圖片只存在本機、會佔用裝置／瀏覽器容量，清除網站資料時圖片也會消失。
- 人設圖縮成 Character Profile 左側 48×48 頭像；原圖不裁掉，點頭像可看完整圖片。
- 胖譜保留較大的成品預覽，因為需要辨識場景、構圖與互動。
- 完整圖片可在 lightbox 檢視、更換或移除。

## QA 抓到、後來反而變成設計規則的東西

- 「三分之四身」這種小文案錯誤 → 讓 UI 與 classifier 一起校正，而不是只改畫面文字。
- 篩選分類會把 Advanced 區塊關掉 → 變成「使用者手動決定開關，重繪不能替他收起來」。
- 刪除 BB 導致 CC 自動變 BB → 變成「建立角色對應後，slot token 是地址，不是單純座位號」。
- 固定 AA／BB → 推出真正的 dynamic character slots，並為多角色 Reference Character Mapping 鋪路。
- Mojito 中深色 secondary／ghost control 過重 → 淺色主題不能只換頁面背景，互動控制也需要完整 theme mapping。
- 胖譜卡沒有圖片仍撐著大預覽框 → 空狀態本身也要有資訊密度規則，有圖與無圖不能共用同一個視覺重量。
- 雙語導覽每格依 label 自己 sizing 造成底色與文字重心漂移 → 導覽 cell 改以最大既有格為共同尺寸，不再讓每格各自長。

## 下一階段（尚未宣稱完成）

- Reference Character Mapping v1：辨認來源 Prompt 裡的角色／指代，讓使用者把來源角色明確對應到 AA、BB、CC…。
- 只在高信心範圍內傳遞代詞與所有格；遇到模糊來源時 fail closed，不靠性別亂猜。
- AI 未來只負責語意／角色辨識，真正的替換仍由本機、可預測的 deterministic engine 執行。
