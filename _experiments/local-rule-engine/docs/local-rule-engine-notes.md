# 胖譜小精靈 Local Rule Engine 實驗版紀錄

## 目的

測試「不使用 API、不要求使用者複製到 ChatGPT/Gemini」時，是否能靠本機規則引擎完成足夠好用的胖譜置換與英文 prompt 組裝。

## 基準

- 主版本保留於 `_snapshots/v1.0-v8`
- 實驗版本位置：`_experiments/local-rule-engine`
- 實驗版服務：`http://127.0.0.1:5178/`

## rule-2 已完成

- 實驗版改用獨立 localStorage key。
- 預設使用本機模式。
- 首頁 icon 換成實驗版頭貼。
- 生成按鈕改為「本機規則生成」。
- 不需要先按拆解，貼上胖譜後可直接生成。
- 小提醒頁新增本機規則拆解表。
- 本機規則目前可拆：
  - 身份保護
  - 人物
  - 外觀
  - 服裝
  - 場景
  - 動作
  - 鏡頭
  - 光線
  - 風格
  - 畫質
  - 負面詞
- 已加入第一批可見性規則：
  - 高領/圍巾可能遮住鎖骨或頸部標記。
  - 長袖/外套/針織可能遮住手腕或手臂配件。
  - 吊帶/露肩適合保留鎖骨或肩膀特徵。
  - 若鏡頭或設定提到耳部，耳飾可保留。

## 下一步候選

- 建立衝突規則：服裝與配件、濾鏡與負面詞、鏡頭與可見度。
- 增加「規則命中信心」分數。
- 讓使用者能把未知片段手動分類並存成新規則。
- 增加一鍵輸出多版本：保守版、寫實版、日系版。

## rule-3 調整

使用者測試發現：

- 本機引擎可生成，但過度摘要，漏掉項鍊、耳機、飲料、廣角、生活感、editorial 等細節。
- `Consistency notes` 不應進入最終胖譜。
- 每個欄位不應顯示同一套操作選項，例如人物不需要「小精靈救救我」，負面詞不應有「套用角色卡」。

已調整：

- 最終 prompt 不再輸出 `Consistency notes`，提醒只留在「小精靈做了什麼」。
- 欄位操作改為依欄位顯示：
  - 人物：原樣保留 / 套用角色卡
  - 服裝、場景、動作、風格：原樣保留 / 小精靈救救我 / 我自己來
  - 比例：原樣保留 / 我自己來
  - 負面詞：原樣保留 / 小精靈整理 / 我自己來
- 新增道具/配件分類。
- 新增英文測試案例需要的規則：
  - bright genuine smile
  - medium-length straight black hair
  - wispy curtain bangs
  - almond-shaped dark brown eyes
  - oversized white graphic T-shirt with colorful landscape prints
  - silver necklace with green butterfly pendant
  - white wireless earbud
  - iced orange juice cup with straw and logo
  - wide-angle perspective
  - vibrant colors
  - candid lifestyle photography
  - minimalist composition
  - editorial style
  - realistic hair strands
  - sharp focus
  - DSLR-quality professional photography

## rule-5 大量補詞典與未知片段策略

補充詞典：

- 外觀：多種髮色、髮型、眼睛、異色瞳、精靈耳、痣/淚痣、刺青、雀斑、體態。
- 服裝材質與特殊服裝：蕾絲、皮革、緞面/絲質、罩衫、圍裙、睡衣、運動服、女僕、Lolita、漢服、禮服。
- 道具：蝴蝶結、雨傘、花束、書本、相機、包包。
- 場景：車內、飯店、廚房、浴室、陽台、電梯、遊樂園、水族館、美術館/博物館、神社/寺廟、祭典、便利商店、洗衣店、溫室、櫻花、秋景。
- 動作：揮手、抱胸、插口袋、跳躍、跳舞、睡姿、吃東西、伸手。
- 鏡頭：特寫、全身、七分身、俯拍、傾斜鏡頭、自拍、POV、淺景深、微距。
- 光線：燭光、月光、煙火光、螢光燈、體積光、陰天光、閃光燈。
- 風格：韓系、中式/國風、原宿、Y2K、街頭、哥德、暗黑學院、偶像、雜誌、拍立得、拍貼、Vlog、低飽和、高對比。
- 負面詞：模糊、低畫質、多臉/多人物、變形。

未知片段策略調整：

原本行為：

- 系統把未命中詞典的片段列在「小精靈還不確定」。
- 只有純英文未知片段會少量保留進最終 prompt。
- 中文未知片段大多不會進最終 prompt，容易造成資訊被刪掉。

問題：

- 這會讓規則引擎看起來能生成，但其實過度摘要。
- 使用者不容易知道哪些內容被丟掉。
- 如果詞典不完整，輸出品質會明顯下滑。

rule-5 新行為：

- 未命中片段改稱「未分類片段」。
- 不衝突的英文未知片段會保守放回最終 prompt。
- 中文未知片段會先經過本機常用語塊翻譯表，能轉英文才放回最終 prompt。
- 可能與角色卡衝突的人物外觀片段，若人物模式是「套用角色卡」，會留在提醒區，不放進最終 prompt。

後續可改善：

- 讓使用者點選未分類片段，指定它是服裝/場景/動作/風格/道具，並存成本機新規則。
- 為未知片段加「保留 / 忽略 / 加入詞典」三個操作。
- 對未知片段做信心分數，而不是只列清單。

## rule-6 舊快取與保守句段保留修正

使用者回報：

- 最終 prompt 仍出現 `Consistency notes`。
- 耳機、手拿飲料、動作細節仍可能被漏掉。

判斷原因：

- 程式已移除 `Consistency notes`，但舊輸出可能仍存在 localStorage，或 service worker 快取仍載到舊版。
- `parsed.engine` 之前會被存進 localStorage，詞典升級後若沒有重新拆解，會沿用舊規則結果。
- 單靠詞典摘要仍容易漏掉英文原 prompt 的完整道具/動作句。

已調整：

- localStorage key 升到 `prompt-sprite-local-rule-engine-v2`，避免沿用舊輸出。
- service worker 升到 `prompt-sprite-local-rule-engine-v6`。
- 每次按生成都強制重新 parse，使用最新規則。
- 原胖譜輸入一改動就清掉舊 parsed。
- 新增 `stripLegacyConsistencyNotes()`，避免舊輸出殘留該段。
- 新增「保守保留的原文句段」：
  - 若原文句子包含 wears / holding / against / captured / illuminated / background 等安全訊號，且不與角色卡身份替換衝突，會保守放回最終 prompt。
  - 小提醒頁會顯示哪些句段是被保守保留的，方便判斷是「直接保留」還是「詞典命中」。
- 加強 earbud / cup / holding 類規則。

## rule-7 誤判修正

核心測試發現：

- `T-shirt` 會被 `shirt` 規則誤判成襯衫。
- `landscape` 會被 `lace` 規則誤判成蕾絲。
- `Captured` 會被 `cap` 規則誤判成帽子。
- `smiling face logo` 會被當成人物臉部衝突，導致手拿飲料原句被排除。

已修正：

- 收窄 shirt / lace / hat 規則，避免單字子字串誤判。
- 服裝、道具、場景、鏡頭、光線句段優先視為安全句段，不因 `face logo` 類詞被排除。
- 保守保留英文句段時，把開頭 `She / He / They` 改成 `the subject`，降低套角色卡後的身份衝突感。
